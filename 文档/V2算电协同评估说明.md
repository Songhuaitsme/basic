# V2 Candidate DQN 算电协同评估

入口 `v2.evaluate_coordination` 只运行一次正式 Candidate DQN 策略，不训练模型，
也不另行运行 Earliest Feasible 策略。反事实候选来自每个 DQN 决策的同一候选集、
同一资源日历快照，因此不会因另一次仿真的资源状态不同而失去逐任务可比性。

## 模型与确定性设置

- 未传 `--model-path` 时，只在 `artifacts/v2/formal/` 中查找文件名包含
  `tou_region` 的模型，排除 `.last.pt` 训练恢复文件，并选择 `training_steps`
  最大的正式策略权重。
- 当前仓库自动选中
  `artifacts/v2/formal/candidate_dqn_seed7_layered_pool_600000_tou_region_from_scratch.pt`。
- 无论自动定位还是显式传入路径，入口都会读取 checkpoint 元数据并要求
  `V1_TARIFF_MODE=tou_region`，防止误用未分区定价模型。
- 评估显式使用 `model.eval()`、`epsilon=0`、固定 seed，并保存模型 SHA-256、
  配置、任务轨迹、拓扑和外生轨迹哈希。
- 分区定价 checkpoint 的特征 schema 与当前 `tou_region` 运行时直接校验；不恢复
  旧模型尺度，也不调整物理定价、任务生成、候选生成、容量约束和调度逻辑。

## 执行

从仓库根目录运行：

```powershell
py -m v2.evaluate_coordination `
  --model-path artifacts/v2/formal/candidate_dqn_seed7_layered_pool_600000_tou_region_from_scratch.pt `
  --seed 42 `
  --arrival-cutoff 288 `
  --output-dir artifacts/v2/evaluation/coordination_v2_seed42
```

默认使用 CPU。确认本机 CUDA 可用后，可额外传入 `--device cuda`。输出目录必须
不存在，入口不会覆盖历史评估；省略 `--output-dir` 时会自动生成带时间戳的目录。

## 输出

- `evaluation_config.json`：完整系统配置、seed、模型绝对路径、训练/评估定价模式、
  命令和来源哈希。
- `evaluation_report.json`：正式评估报告；周期明细压缩为空，但保留周期数量、任务、
  决策、账本和诊断。
- `task_metrics.csv`：任务来源、目标节点、最早/实际开始、主动等待、成本与绿电反事实、
  SLA 和空间/时间迁移标记。
- `decision_metrics.csv`：候选数量、选中候选、Earliest Feasible 候选、提交状态和决策审计。
- `time_metrics.csv`：活动任务、CPU 负载、功率需求、绿电出力/使用、电价和绿电覆盖。
- `node_metrics.csv`：节点任务、CPU 小时、能耗、绿电供给/使用、利用率和电费。
- `system_metrics.json`：总体、迁移和 Earliest Feasible 反事实汇总及指标定义。
- `representative_tasks.json`：最多 5 个代表任务；同样内容会在终端打印。

迁移比例的分母是成功提交预留的任务，不是所有到达任务。`earliest_*` 与
`selected_*` 成本和绿电字段是决策时估计值；系统总成本、任务能耗和归因绿电是任务
完成后的正式账本值。`sla_satisfied` 表示任务完成且开始时间未超过绝对最晚开始限制。
