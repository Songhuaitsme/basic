# V2 性能改造说明

V2 是运行时性能版本，不修改已经冻结的 V1 需求、任务、候选、模型、指标和聚合 schema。现有 V1 模型可以直接由 V2 评估，旧的 V1 完整训练 checkpoint 会在加载时自动重建 V2 索引。

## 已实现

- 任务状态维护增量计数和 task-id 集合，状态统计为 O(1)。
- 队列维护 EDF 堆、Pending 集合和截止期堆，队列选择及到期处理为 O(log N) 摊销复杂度。
- 训练保留逐周期到达随机序列，但空闲周期只推进虚拟时间；仅在任务到达、队列非空、物理事件到期或截止期到期时执行完整调度。
- ReservationCalendar 按版本缓存不可变快照，并建立 reservation/resource 双向分配索引。
- 资源提交使用局部 undo log，释放按 reservation 定位，不再复制或过滤全部活动分配。
- 没有 eligible task 时不构造候选指标 evaluator。
- 分层候选池按 node/path 分组调用批量指标接口。
- V2 评估默认 periodic 审计且结束时强制完整审计，默认输出 compact 报告。
- V2 默认候选 chunk 为 65,536，完整运行 checkpoint 间隔为 50,000 周期。

## 入口

```powershell
# V2 训练（默认跳过空闲调度周期）
py -m v2.train_v2 --steps 600000 --seed 7 --output artifacts/v2/formal/candidate_dqn_seed7.pt

# 从现有 V1 checkpoint 继续
py -m v2.train_v2 --steps 650000 --seed 7 --resume artifacts/v1/formal/candidate_dqn_seed7_layered_pool_600000_v2.last.pt

# V2 评估（默认 periodic audit + compact report）
py -m v2.evaluate_v2 --policy candidate_dqn --model-path artifacts/v1/formal/candidate_dqn_seed7_layered_pool_600000_v2.pt
```

训练可用 `--no-skip-idle-cycles` 回退到逐周期完整调度。评估可用 `--audit full|periodic|final` 和 `--report-mode compact|full` 调整审计及输出。

## 五策略配对评估与源数据导出

`v2.evaluate_five_policies` 会对同一组 seed 依次运行
`earliest_feasible`、`lowest_cost`、`highest_green`、`equal_weight` 和
`candidate_dqn`。所有策略共享相同的任务、外生轨迹和评估参数；运行结束后会自动调用
`v2.export_five_policy_metrics` 检查配对元数据并导出全部指标。

```powershell
# 单 seed 完整仿真日检查
py -m v2.evaluate_five_policies `
  --seeds 42 `
  --arrival-cutoff 288 `
  --model-path artifacts/v2/formal/candidate_dqn_seed7_layered_pool_600000_from_scratch.pt

# 至少 10 个未见 seed 的正式配对评估；中断后可用 --resume 续跑
py -m v2.evaluate_five_policies `
  --seeds 101 103 107 109 113 127 131 137 139 149 `
  --arrival-cutoff 288 `
  --model-path artifacts/v2/formal/candidate_dqn_seed7_layered_pool_600000_from_scratch.pt `
  --resume

# 已经存在五策略 JSON 时，可单独重新生成源数据表
py -m v2.export_five_policy_metrics `
  --input-dir artifacts/v2/evaluation/five_policy

# 生成中文五策略 HTML 对比报告
py -m v2.compare_five_policies
```

默认输出到 `artifacts/v2/evaluation/five_policy/`：

- `seed_<seed>/*.json`：五种策略的原始正式评估报告；
- `source_data/metrics_long.csv`：每行一个 seed、策略和指标，保留状态、原因、分子与分母；
- `source_data/metrics_wide.csv`：每行一个 seed 和指标，五种策略的值并列；
- `source_data/task_metrics.csv` / `decision_metrics.csv`：任务级结果与逐次决策审计；
- `source_data/time_metrics.csv` / `node_metrics.csv` / `network_metrics.csv`：时间、节点和网络细粒度指标；
- `source_data/runtime_metrics.csv`：整体、决策、候选生成、策略选择、推理和提交耗时；
- `source_data/source_manifest.csv`：源文件、版本、模型和配对轨迹哈希；
- `source_data/analysis_validation.json`：完整性与可比性检查结果。
- `comparison_report/report.html`：成本、绿电、可靠性、SLA 和等待行为中文对比报告；
- `comparison_report/dqn_vs_equal_weight.csv`：DQN 相对 Equal-weight 的差值与配对区间；
- `comparison_report/best_strategy_by_metric.csv`：全部指标的最佳策略或“不判优”标记。

已有输出默认不会覆盖。使用 `--resume` 只复用 seed、cutoff、系统版本和模型哈希匹配的有效报告；确需重跑时使用 `--overwrite`。可先加 `--dry-run` 检查将要执行的全部命令。

完整的指标定义、判优方向、四层下钻方法和代码数据链路见 [V2评估体系说明.md](V2评估体系说明.md)。

## 兼容性与验证

- `SYSTEM_VERSION` 标记为 `2.0`；其余正式 schema 版本保持 `1.0`。
- 同 seed 的 120 周期对照验证中，V1 全周期与 V2 空闲周期跳过得到相同 transition/update 数，模型与 target 网络参数逐 tensor 完全一致。
- 旧 600,000 周期 checkpoint 已验证可加载并重建状态、队列和资源索引。

## 后续优化

- 多 seed、多 policy 评估的多进程任务编排。
- 动态计费模型内部的完全向量化；当前分层池已经批量调用接口，但某些计费分支仍会在接口内部逐项计算。
- 将运行时 checkpoint 进一步拆成模型 checkpoint 与可恢复仿真快照。
