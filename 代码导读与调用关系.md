# 代码导读与调用关系

本次中文注释覆盖仓库登记的 159 个 Python 文件，包括业务源码、测试和少量分析脚本。文件开头说明主要功能、包含内容及项目模块依赖；函数定义或装饰器前说明职责、可定位的上游及主要下游。原有文档字符串、业务语句和配置值保持原样。生成的网页资源、模型、数据和浏览器缓存不在此次范围内。

## 如何阅读注释

- “模块上游”表示导入依赖，不表示运行时一定会调用。
- “上游（直接调用）”列出能够通过函数名、导入别名、同类方法或显式父类引用定位的调用方。通过对象属性、策略接口及函数赋值发生的动态调用可能不在列表中。
- “调用上下文”补充核心流程中的动态关系；“调用约定”说明框架、回调或命令行的触发方式。
- “下游调用”保留源码中的调用表达式，便于定位实现。长列表只列主要项，完整调用与分支以源码为准。

## 运行时版本装配

| 版本  | 工厂与入口行为                                                          |
| --- | ---------------------------------------------------------------- |
| V1  | `create_v1_runtime` 装配基础设施、任务管理、资源日历、预测、核算账本、候选生成器、策略和调度器。       |
| V2  | 训练与评估入口转发至 V1 主流程，提供 V2 版本、输出及批处理默认参数。                           |
| V3  | 先调用 V1 工厂，再替换扫描线能源核算器和 V3 候选生成器，并重接账本。                           |
| V4  | 先调用 V3 工厂，再装配 `NetBenefitGatePolicy`、等待净收益门控及 `V4Scheduler`。     |
| V5  | 先调用 V4 工厂，再替换为 `V5CandidateGenerator`，接入决策内缓存、静态容量过滤和向量化 Pareto。 |
| V6  | 先调用 V5 工厂，再替换为 `V6EnergyAccounting`，同步更新运行时和调度器的账本引用。            |

工厂链为 `create_v6_runtime → create_v5_runtime → create_v4_runtime → create_v3_runtime → create_v1_runtime`。

V3–V6 的 `_entrypoint.py` 通过上下文临时替换 V1 训练和评估模块中的工厂引用。V5/V6 适配继续嵌套上层上下文，退出时由这些上下文恢复入口。因此，确认实际使用哪个实现时，需要一起看版本入口、适配上下文和运行时工厂。

## 训练、调度与学习

训练入口 `train_vN.main` 经适配进入 `v1/train_v1.py::main → run_training`。主流程构建或恢复运行时，执行预检和预热，驱动任务到达、调度、奖励归因与经验训练，并按配置保存日志、模型、恢复检查点和固定轨迹验证结果。

单周期由 `V1Scheduler.run_cycle` 编排：

1. `EventEngine.advance_to` 推进物理事件，处理完成任务的实际核算。
2. 队列管理器唤醒待处理任务，接收新到达任务并选取本周期可调度任务。
3. `_schedule_one` 为每个任务准备候选，通过策略接口选择方案。
4. `ReservationManager.commit_selected` 协调提交，`ReservationCalendar.try_commit` 检查版本与资源容量。
5. 成功预留登记到事件引擎，后续周期处理传输、计算、完成或失败；未提交任务按原因进入待重试或终止状态。

V4 调度器继承上述流程，扩展等待门控的决策诊断记录。

候选生成器结合 `StaticPathProvider`、`TransmissionModel` 和 `ReservationCalendar` 检查路径、传输与 CPU 约束。完整候选流和分层候选池有各自的准备路径，模式由配置和上下文决定。能源核算器的 `candidate_metric_evaluator` 提供绑定资源快照的评分回调。

`CandidateFeatureEncoder` 编码候选，`SharedCandidateQNetwork` 输出 Q 值，`CandidateDQNPolicy` 选择候选并保存选择轨迹。训练会话将轨迹、提交奖励、实际结算修正和终止事件组合成回放经验，再由 `CandidateDQNTrainer` 计算 Double DQN 目标并更新网络。

V4 等待门控发生在基础策略选出候选之后。门控不通过时回退到最早可行候选，并同步修正最新的 DQN 选择轨迹，使训练记录对应实际执行方案。

## 评估与能源核算

评估入口 `evaluate_vN.main` 经适配进入 V1 主流程，`EvaluationRunner.run_frozen_policy` 组织固定轨迹下的预热、正式测量及任务排空。`evaluation_v1/metrics.py` 汇总任务表现，`diagnostics.py` 汇总资源诊断，`statistics.py` 进行配对统计。V2 的五策略与算电协同工具继续整理这些结果，输出统一明细和比较报告。

`MetricsLedger.record_completed_reservation` 将完成预留交给能源核算器实际结算，`finalize_after_full_settlement` 汇总最终结果。V3 通过节点功率事件扫描建立积分索引；V6 保留积分规则，用对象身份缓存和只读数组减少重复开销。

能源指标回调中的局部 `evaluate` 通过函数返回值被调用，`evaluate_batch` 则挂在返回函数的同名属性上供批处理使用。这些关系属于动态绑定，不能仅依赖静态直接调用列表理解。

## 共享模块、旧版与测试

`shared` 为各版本提供基础设施、任务与计价配置；`legacy` 保留独立的旧环境及 DQN/GNN 训练评估流程。`tests` 和各版本的 `tests` 子包由 `unittest` 发现，`setUp` / `test_*` 有测试框架隐式调用。模型 `forward`、数据类 `__post_init__` 及序列化方法也由各自框架或协议触发。

在仓库根目录可运行：

```powershell
py -3 -m unittest discover -s tests -t .
py -3 -m unittest v3.tests.test_sweep_line_energy v4.tests.test_wait_gate v5.tests.test_candidate_generator v5.tests.test_profiling v6.tests.test_energy
```
